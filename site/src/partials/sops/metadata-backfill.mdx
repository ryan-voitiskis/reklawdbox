## Constraints

- **Labels are enrichment-dependent.** Labels come from Discogs enrichment cache, with MusicBrainz and Bandcamp as fallbacks. Tracks without cached enrichment from any source are skipped, not fetched.
- **Years use a priority cascade.** `backfill_years` tries multiple sources in order: file tags → folder path `(YYYY)` → Discogs enrichment → Beatport enrichment → MusicBrainz enrichment → Bandcamp enrichment. For tracks still missing years after the tool runs, the agent researches release dates.
- **No auto-tagging without review.** The backfill tools stage non-conflicting values automatically, but conflicts require human approval before staging.
- **XML export only.** All changes flow through `update_tracks` → `preview_changes` → `write_xml`.
- **Self-released tracks are skipped (labels only).** Discogs "Not On Label" entries are filtered out — they carry no useful signal.
- **Year 0 = unset.** Rekordbox uses 0 for tracks with no year. Rekordbox often fails to import year tags from WAV files, so year=0 does not mean the file lacks a year tag — check before assuming it's missing.

## Prerequisites

```
cache_coverage(has_label=false)
```

Check Discogs coverage for unlabeled tracks. If below 80%, hydrate first:

```
enrich_tracks(has_label=false, skip_cached=true, providers=["discogs"], max_tracks=50)
```

Repeat until Discogs coverage reaches 80%+. Report progress between batches.

## Steps

### 1. Backfill labels

```
backfill_labels()
```

The tool scans the entire collection (excluding samples), looks up each track's Discogs enrichment, and:
- **Fills** empty labels from enrichment (auto-staged)
- **Skips** tracks where current label matches enrichment
- **Reports conflicts** where current label differs from enrichment (not staged)

Report the summary: "Backfill complete: N labels staged, N already correct, N conflicts, N without enrichment."

### 2. Resolve label conflicts

Group conflicts by pattern for efficient review:

#### Artist-name-as-label vs actual label

When the current label is the artist's name and Discogs has an actual label, suggest the Discogs label — it provides a stronger signal than the artist name.

```
Artist-name-as-label conflicts (N):
 #1  Fantastic Man — Antiboudi | Fantastic Man → Mule Musiq
 #2  Fantastic Man — Diaspora | Fantastic Man → Mule Musiq
 ...
```

Ask user: **"Approve all, or reject/change specific numbers."**

Stage approved changes via `update_tracks`.

#### Label name variations

When both labels refer to the same entity with different formatting (e.g. "Palette" vs "Palette Recordings", "Loma Vista" vs "Loma Vista Recordings"), suggest keeping the current label — it was set intentionally.

Present these for confirmation but recommend no change.

#### Genuine disagreements

When the Discogs label is a different entity entirely (e.g. different pressing, compilation, or wrong match), present individually with context:

```
 #N  Artist — Title | Current: Label A → Discogs: Label B
```

Ask user to pick one, or skip.

Stage approved changes via `update_tracks`.

### 3. Backfill years

```
backfill_years()
```

The tool scans the entire collection (excluding samples) and tries six sources in priority order for each track with year=0:

1. **File tags** — reads year from the audio file's metadata (ID3v2, Vorbis Comment, RIFF INFO). Most reliable since the user tagged it.
2. **Folder path** — extracts year from a `(YYYY)` suffix in the parent directory name (e.g. `Album (2019)/`).
3. **Discogs enrichment** — falls back to the cached Discogs release year.
4. **Beatport enrichment** — falls back to the cached Beatport `publish_date`/`release_date`.
5. **MusicBrainz enrichment** — falls back to the cached MusicBrainz `first-release-date`.
6. **Bandcamp enrichment** — falls back to the cached Bandcamp `release_date`. Particularly effective for underground/independent electronic music.

The first source to produce a valid year (1900–2099) wins. Non-conflicting fills are auto-staged. Tracks where the current year differs from a source are reported as conflicts.

Note: Beatport date extraction requires enrichment cache entries created after this feature was added. For tracks with older cache entries, re-enrich with `enrich_tracks(providers=["beatport"], force_refresh=true)` to populate the `release_date` field.

Report the summary: "Year backfill complete: N years staged (N file tags, N folder paths, N Discogs, N Beatport, N MusicBrainz, N Bandcamp), N already correct, N conflicts, N without any source."

### 4. Resolve year conflicts

Group year conflicts by pattern:

#### Original vs reissue

When the current year and Discogs year differ, it's often because one is the original release and the other is a reissue. Prefer the earlier year — it reflects the track's era more accurately for genre classification and set building.

```
Year conflicts (N):
 #1  Artist — Title | Current: 2020 → Discogs: 1993
 #2  Artist — Title | Current: 1995 → Discogs: 2018
 ...
```

Ask user: **"Approve earlier year for all, or review individually?"**

Stage approved changes via `update_tracks`.

### 5. Research remaining year gaps

After `backfill_years`, some tracks may still have year=0 with no source data. The tool reports these as `remaining_year_zero`. For these tracks:

#### 5a. MusicBrainz lookup

Use the `lookup_musicbrainz` tool for each remaining track:

```
lookup_musicbrainz(track_id="...")
```

The tool searches MusicBrainz for the recording (score ≥ 90), extracts `first-release-date` as the year and the label from the best matching release, and caches the result. Rate limiting (1 req/sec) is handled automatically.

Batch results and present for user approval, then stage via `update_tracks`.

#### 5b. Bandcamp lookup

For tracks MusicBrainz doesn't cover, try Bandcamp — it has a high hit rate for underground/independent electronic music:

```
lookup_bandcamp(track_id="...")
```

The tool searches Bandcamp for the track, fetches the detail page for structured metadata (JSON-LD), and extracts `release_date`, `label`, and `tags`. Results are cached. Rate limiting (1 req/1.5s, 2 requests per lookup) is handled automatically.

Batch results and present for user approval, then stage via `update_tracks`.

#### 5c. Web research for remaining gaps

For tracks neither MusicBrainz nor Bandcamp cover:

1. **Group by artist** for efficient lookup.
2. **Search for release dates** — use web search, Discogs links, or label catalogs to find the original release year.
3. **Present findings** grouped by confidence:
   - **High confidence** (exact release found): present for bulk approval.
   - **Uncertain** (multiple candidates or approximate): present individually with context.
4. **Stage approved years** via `update_tracks`.

Skip tracks where no release information can be found — some self-released or private tracks have no public date.

### 6. Export

```
preview_changes()
```

Ask user: "Export these changes to XML?"

```
write_xml()
```

Report output path, then walk the user through the Rekordbox import:

1. **Add XML to Rekordbox** — Open Preferences → Advanced → rekordbox xml → **Imported Library** → Browse → select the exported XML file.
2. **Open the XML view** — In the sidebar, click the **"Display rekordbox xml"** icon. The imported tracks appear under "All Tracks".
3. **Import into collection** — Select all tracks (Cmd+A), right-click → **Import To Collection**. When prompted "Do you want to load information in the tag of the library being imported?", click **Yes** (tick "Don't ask me again" for bulk imports).
