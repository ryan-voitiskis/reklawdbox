Grow and inspect an unordered pool whose members are mutually compatible for
live improvisation, then optionally export the locked pool as a Rekordbox
playlist.

## Start here

<WorkflowQuickStart id="pool-building" />

```
Build a track pool from my collection.
```

## What happens next

1. **Set the intent.** Confirm seed or candidate tracks, discovery scope, pool
   size, and whether you perform with master tempo enabled.
2. **Grow the pool.** Compare suggested additions against the approved members;
   the score is symmetric because the crate must work in either direction.
3. **Inspect cohesion.** Review weak members and surprising discoveries, then
   keep, replace, or remove them based on how the pool should feel live.
4. **Lock and export.** Approve the final membership, preview unrelated staged
   metadata, and optionally create playlist XML.

## Decisions and approval checkpoints

- Valid seeds/candidates and parameters are the only hard requirements. Missing
  BPM, key, genre, or analysis weakens an axis instead of blocking the pool.
- Stratum contributes BPM/key evidence. Essentia is recommended for energy,
  brightness, rhythm, and timbral evidence, but unavailable axes degrade
  gracefully.
- `balanced` prioritizes BPM and energy while using timbre for discovery;
  `timbral` increases cross-genre sonic discovery.
- Pool tools default to `master_tempo=false`, accounting for pitch shift when
  tempo changes. Set it to `true` if that matches your Rekordbox performance
  setup.

Unlike [Set Building](/workflows/set-building/), there is no fixed energy arc or
track order. See [Pool Discovery](/concepts/pool-discovery/) for the scoring and
expansion model.

## What changes and how to recover

Current pool membership lives in the conversation. After a restart, re-submit
the approved members; saved presets and exported XML persist. If growth stops
early, widen filters, change seeds, or relax the scoring goal. Timbral
normalization statistics may be stored locally when enough Essentia vectors
exist.

Playlist export writes and clears unrelated staged metadata as well as the
playlist, so review all prepared changes first and complete a separate metadata
XML handoff when needed. Export fails closed unless the built-in database backup
succeeds or the configured custom backup script exits zero. A failed export
restores staged metadata for retry.

## Finish in Rekordbox

Keep the XML and follow the
[playlist XML import steps](/reference/xml-export/#importing-into-rekordbox).
Confirm the imported playlist name and count before calling the pool locked or
deleting the XML. Use the separate All Tracks flow for any included staged
metadata.
