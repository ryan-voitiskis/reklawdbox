Five sessions, each with clear entry and exit criteria. Follow in order — later sessions depend on earlier ones.

<Aside type="tip" title="Start with a health scan">
  Before Session 1, run a [Library Health](/workflows/library-health/) scan to find broken links, orphan files, and duplicates. Fixing structural issues first prevents wasted work in later sessions.
</Aside>

<Aside type="danger">
  **Session 1 writes directly to files. Sessions 3–5 stage changes as XML** — the Rekordbox database only updates after you import the XML file. Each session reads from the database, so you **must** complete each checkpoint before starting the next session. Session 2 is a CLI command, not an agent session.
</Aside>

## Why order matters

**Clean metadata → accurate enrichment → label data → genre signals**

Enrichment matches on artist/title — typos cause missed matches. Genre classification uses enrichment + audio analysis as evidence. Working out of order means poor results or re-running workflows.

## Sessions

### Session 1: Collection Audit

<Badge text="Entry" variant="note" /> MCP server connected.

**Paste into your agent to start this session:**

```
Audit my collection for naming and tagging issues.
```

To scope to specific directories:

```
Audit [/path/to/music, /another/path] for naming and tagging issues.
```

Fix artist names, track titles, and naming conventions. Cleaning these first improves enrichment match rates.

<LinkCard title="Collection Audit workflow" href="/workflows/collection-audit/" />

#### CHECKPOINT

No XML export — Collection Audit uses direct file operations. Spot-check corrected tracks in Rekordbox.

<Aside type="tip">
  Natural context-reset point — close this session and start fresh for Session 2.
</Aside>

---

### Session 2: Enrichment

<Badge text="Entry" variant="note" /> Clean metadata — Session 1 complete.

```sh
reklawdbox hydrate --cpu overnight -y
```

`--cpu overnight` uses max cores; `-y` skips confirmation. Use `--artist`, `--genre`, or `--added-after` to scope.

**Exit:** Re-run `reklawdbox hydrate` — it reports remaining gaps. All providers must be at 100%.

---

### Session 3: Metadata Backfill

<Badge text="Entry" variant="note" /> All tracks enriched — Session 2 complete.

**Paste into your agent to start this session:**

```
Find tracks missing labels and years in my collection and fill them from enrichment data.
```

Labels are the strongest genre signal for electronic music, years provide era context for classification and set building, and albums round out metadata for library browsing. The agent checks enrichment coverage, backfills empty labels, missing years, and albums from all enrichment providers, and presents conflicts grouped by pattern for your review.

### Session 4: Genre Classification

<Badge text="Entry" variant="note" /> Labels backfilled — Session 3 XML imported.

**Paste into your agent to start this session:**

```
Classify genres for my ungenred tracks.
```

The agent normalizes aliases first (e.g. `Hip-Hop` → `Hip Hop`), then classifies ungenred tracks in batches. You review results grouped by confidence level — high and medium can be approved in bulk, low and insufficient need per-track review.

### Session 5: Genre Audit

<Badge text="Entry" variant="note" /> Genres classified — Session 4 XML imported.

**Paste into your agent to start this session:**

```
Audit my existing genre tags.
```

The agent checks existing genre tags against enrichment and audio evidence. Only conflicts and manual-review tracks are surfaced — confirmed genres are skipped. Review and approve or reject in batches.

## Skipping sessions

- **Metadata already clean?** Start at Session 2.
- **Already enriched?** Re-run `reklawdbox hydrate` — if all providers are at 100%, jump to Session 3.
- **Labels and years present?** Skip Session 3.
- **No ungenred tracks?** Skip Session 4.
- **No existing genre tags?** Skip Session 5.
