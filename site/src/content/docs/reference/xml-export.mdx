## XML structure

A minimal Rekordbox XML file looks like this:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<DJ_PLAYLISTS Version="1.0.0">
  <PRODUCT Name="rekordbox" Version="7.2.10" Company="AlphaTheta"/>
  <COLLECTION Entries="12">
    <TRACK TrackID="1" Name="Track Title" Artist="Artist Name"
           Genre="Deep House" Comments="Great track" Rating="204"
           Location="file://localhost/Users/.../track.flac"
           Tonality="Am" AverageBpm="124.00" Colour="0x25FDE9"/>
  </COLLECTION>
  <PLAYLISTS>
    <NODE Type="0" Name="ROOT" Count="1">
      <NODE Type="1" Name="My Set" Entries="12" KeyType="0">
        <TRACK Key="1"/>
      </NODE>
    </NODE>
  </PLAYLISTS>
</DJ_PLAYLISTS>
```

---

## What reklawdbox exports

**Editable fields** (actively written by `write_xml`): Genre, Comments, Rating (1-5), Colour, Label.

**Pass-through fields** (read from DB, included in export): title, artist, album, remixer, label, year, key, BPM, file location, file kind, bit rate, sample rate, play count, date added, total time.

**Hardcoded defaults** (not read from DB): Composer, Grouping, Mix (`""`), Size, DiscNumber, TrackNumber (`0`).

Playlists are included when `write_xml` is called with the `playlists` parameter.

<Aside type="caution">
  Beat grids (TEMPO) and cue points (POSITION_MARK) are **not** included in the export. They're preserved in the Rekordbox database and unaffected by reimport.
</Aside>

## Importing into Rekordbox

<Steps>

1. **Close Rekordbox** before writing XML (avoids file lock conflicts).

2. **Open Rekordbox** and go to **File > Import > Import Playlist/Collection**.

3. **Select the XML file.** Tracks appear in the **rekordbox xml** sidebar section.

</Steps>

<Aside type="caution" title="The reimport bug">
In Rekordbox 5.6.1+ (all RB6/RB7), existing tracks are **not** updated on standard import.

**Workaround:** Right-click the imported playlist → **Import To Collection**, then select all tracks (Cmd+A), right-click → **Import To Collection** again. The second pass forces metadata overwrite for existing tracks.
</Aside>

## What survives a round-trip

**Preserved:** Genre, Comments, Rating, Colour, title, artist, album, remixer, label, key, BPM, playlist structure.

**Not included:** Cue points, beat grids, My Tags, Hot Cue Banks, phrase analysis, smart playlist criteria, waveform data (ANLZ files). These remain in the Rekordbox database — reimport doesn't touch them.

---

## Rating values

Rekordbox maps stars to 0/51/102/153/204/255. reklawdbox converts automatically — you specify 1-5 in tool calls.

---

## Track colors

Rekordbox supports eight track colors. Use these hex values in reklawdbox:

| Color     | Hex        |
| --------- | ---------- |
| Rose      | `0xFF007F` |
| Red       | `0xFF0000` |
| Orange    | `0xFFA500` |
| Lemon     | `0xFFFF00` |
| Green     | `0x00FF00` |
| Turquoise | `0x25FDE9` |
| Blue      | `0x0000FF` |
| Violet    | `0x660099` |

---

## Key format

Rekordbox XML uses classic notation (`Am`, `Bb`, `F#m`). Camelot is display-only in the UI. reklawdbox converts automatically.

---

## Backup behavior

Before export, reklawdbox checks for a backup script (in order): `REKLAWDBOX_BACKUP_SCRIPT` env var, then built-in probe paths. If found, it runs synchronously with `--pre-op` before writing. Failures log warnings but don't block export.

XML files are written to `~/reklawdbox-exports/` by default.

---

<Aside type="tip" title="Notes">
- **Location paths** use `file://localhost/` with URL encoding — handled automatically.
- **Collection count** (`Entries`) must match the actual `<TRACK>` count or Rekordbox rejects the file.
- **Import is additive only** — never deletes tracks from your collection.
- **Genre is free text** — no predefined list in Rekordbox.
</Aside>
